# 要件定義書
## プロジェクト：「輝きの再点火」装置（仮称）

**作成日：** 2026-03-20
**作成者：** takato + 七者討論に基づく
**ステータス：** Draft v1

---

## 1. プロジェクト概要

### 1.1 目的
コンテキストスイッチ（仕事、疲労、日常の惰性）によって失われた思考の「輝き」を、外部に保存された断片を通じて再点火するための装置を構築する。

### 1.2 ではないもの
- リマインドアプリ（「楽しかった思い出をもう一度」ではない）
- タスク管理ツール（やりかけのことを思い出させるものではない）
- セルフヘルプ/メンタルヘルスアプリ（治療ではなくケア）
- SNS/ソーシャルアプリ（他者との共有を目的としない）
- 検索ツール（クエリベースの情報取得ではない）

### 1.3 コアコンセプト
- **螺旋：** 同じ場所に戻るのではなく、回帰するたびに差異が生まれる
- **不在の頂点：** 言語化しきれない欲望の痕跡を通じて、その不在を感じ取る
- **生活に潜むagent：** 押し売りではなく、生活の余白にそっと存在する

---

## 2. ユーザー定義

### 2.1 プライマリユーザー
- Scrapboxで日常的に思考を記録している個人
- 複数の関心領域を持ち、それらの間にリンクを張る習慣がある
- コンテキストスイッチ（仕事↔個人の思考）を日常的に経験する
- SNSの消費ループに対して自覚的な違和感を持っている

### 2.2 ユーザーの状態（使用タイミング）
- 仕事から帰宅し、疲れている
- スマホを手に取ったが、何を開くか決めていない
- 思考の輝きを感じていた頃の文脈を失っている
- 能動的に何かを検索する気力はない

## 3. 機能要件

### 3.1 データソース連携

#### 3.1.1 Scrapbox同期
- Scrapbox APIを通じてユーザーのプロジェクトを同期
- ページ本文、リンク構造、画像、外部URLを取得
- 定期的な差分同期（新規ページ・更新ページの反映）

#### 3.1.2 リンクグラフ構築
- ページ間のリンク構造をグラフとして構築・保持
- 各ノード（ページ）のメタデータ：作成日、更新日、リンク数、テキスト量
- エッジ（リンク）の属性：直接リンク、間接リンク（共有リンクを介した接続）
- **リンクグラフとRAGインデックスは独立した2つのデータストアとして設計する**
  - RAGインデックス（embedding）にはページ本文チャンクの情報のみを格納する
  - リンク情報はembeddingに含めない（リンク先のテキストをチャンクに混入しない）
  - 理由：リンクをembeddingに含めると「意味的に遠いがリンクで繋がっている」という乖離が検出不能になるため

#### 3.1.3 外部素材ソース（将来拡張）
- Spotify（ページ内で言及された曲、またはagentが連想した曲）
- 書籍情報（ISBN、書影、著者情報）
- 画像（ページ内の画像、OGP画像）
- その他webリソース

### 3.2 断片選択エンジン

#### 3.2.1 イマージュの抽出
- Scrapboxのページを「イマージュ」単位で分節する
- イマージュの単位はメディア形式ではなく知覚的自立性に基づく
  - 一語〜数段落のテキスト
  - 画像単体
  - テキスト＋画像の組み合わせ
  - 埋め込みURL（OGP情報含む）
- LLMを用いてイマージュの自立性を判定

#### 3.2.2 断片選択ロジック
- **近傍探索（約70%）：** リンクグラフ上で焦点ページから1-3ホップ以内の断片（グラフ探索）
- **跳躍探索（約30%）：** リンクグラフ上で遠いが弱い繋がり（共有リンク、同時期編集等）を持つ断片、またはagentが外部から持ち込む素材
- **特権的な扱い：** 意味的に遠いがリンクで繋がっているノード対（「間のリンク」）
  - 検出方法：グラフ距離（近い）× embedding距離（遠い）の乖離が大きいノード対に高スコアを付与
  - embeddingはこの乖離計算の補助としてのみ使用する
- **時間的フィルタリング：** 直近の記述はタスク化衝動を誘発するため、確率を下げる（完全除外はしない）

#### 3.2.3 選択の原則
- 付きすぎず離れすぎず（連歌の付け合い）
- 最適化しすぎない（差異の反復のために連想性とランダム性を保つ）
- ユーザーの状態を推定しない（刺さるかどうかの判断はユーザーに委ねる）

### 3.3 生成エンジン

#### 3.3.1 焦点イマージュの選択
- 断片選択エンジンから選ばれたイマージュを、ウィジェット表示用の焦点とする
- 日に2-3回、非等間隔で更新

#### 3.3.2 webページ生成（レイヤー2）
- 焦点イマージュを起点に、関連する断片と外部素材を集約
- LLMが「編集」を行う：
  - 要約しない
  - 関係を説明しない
  - 異なる素材を並べ、余白で繋ぐ
  - 変奏する（同じ焦点から毎回異なるページを生成）
- レイアウトはエディトリアルデザイン（カード型ではなく、余白が呼吸する一枚の流れ）
- 各素材の出典は、主張しないが辿れる（長押し等で表示）

#### 3.3.3 一回性の保証
- 同じ焦点イマージュから、毎回異なるページが生成される
- 過去の生成履歴を考慮し、同一の組み合わせを回避

### 3.4 保存機能

#### 3.4.1 地層としての保存
- 生成されたwebページを時系列で保存
- 目的は再体験ではなく、螺旋の軌跡の観察
- 同じ焦点から異なる時点で生成されたページを比較可能に

### 3.5 UIレイヤー

#### 3.5.1 レイヤー1：存在（ウィジェット）
- **プラットフォーム：** iOS WidgetKit（Small / Medium / ロック画面対応）
- **表示内容：** 焦点イマージュ＋周辺の気配（ブラー/フェード表示）
- **インタラクション：** 見るだけで完結可能。タップでレイヤー2へ遷移
- **更新：** 日に2-3回、非等間隔
- **起動時：** 0.5秒のリズム転調（アニメーションのイージングで日常のテンポから離脱）

#### 3.5.2 レイヤー2：体験（生成ページ）
- **形式：** webページ（webview内で表示）
- **レイアウト：** エディトリアルデザイン。テキスト、画像、音楽プレーヤー、書籍情報が余白を通じて一つの流れとして構成
- **出典表示：** 各素材に薄いインジケータ。長押しで出典情報表示
- **参照リンク：** Scrapbox、Spotify、書籍ページ等への遷移リンク（レイヤー3）

#### 3.5.3 レイヤー3：参照（外部遷移）
- 各種外部サービスへの遷移
- Scrapboxは参照先の一つであり、特権的ではない

## 4. 非機能要件

### 4.1 UX原則（最重要）

| # | 原則 | 詳細 |
|---|------|------|
| 1 | 押し売りしない | 通知を送らない。ウィジェットの受動性に徹する |
| 2 | 罪悪感を生まない | 使用頻度の表示、ストリーク、バッジ、「久しぶりですね」を一切排除 |
| 3 | オプトアウトが常に容易 | いつでも閉じられる。閉じたことに対するフィードバックなし |
| 4 | 説明しない | agentは素材間の関係を明示的に説明しない |
| 5 | コントロール感を奪わない | ユーザーが深さを自分で決める。推定しない |

### 4.2 パフォーマンス
- ウィジェット表示：キャッシュ済みデータから即座に表示
- ページ生成：タップから3秒以内に表示開始（プログレッシブレンダリング可）
- Scrapbox同期：バックグラウンドで定期実行、UIをブロックしない

### 4.3 プライバシー
- Scrapboxの内容はユーザーのデバイスまたはユーザー専用のストレージに保持
- 第三者へのデータ共有なし
- LLM APIへの送信は断片単位（ページ全体を送信しない設計を検討）

### 4.4 プラットフォーム
- **Phase 1：** iOS（WidgetKit + SwiftUI）
- **Phase 2：** watchOS（コンプリケーション）、macOS（メニューバー）を検討
- **コア生成エンジン：** webページ生成部分はプラットフォーム非依存に設計

## 5. agentの設計原則

### 5.1 人格
- ユーザーの好みに最適化されすぎない（他者性の維持）
- ユーザーの言葉の痕跡を帯びているが、異なる視座から編集する
- キュレーターではなくDJ

### 5.2 編集の原則
- **本歌取り：** ユーザーのScrapboxの記述を本歌として、それを踏まえつつずらす
- **付きすぎず離れすぎず：** 連歌の付け合いの距離感
- **余白：** 素材間の関係を余白に委ねる。明示しない

### 5.3 外部素材の導入
- ユーザーのScrapbox内で言及された外部リソースの取得（自動抽出）
- agentがScrapboxの内容から連想した外部リソースの提案
- 配合比は約七（自己由来）対三（agent由来）

## 6. 技術スタック（暫定・要検討）

| コンポーネント | 候補 | 備考 |
|--------------|------|------|
| iOSアプリ | SwiftUI + WidgetKit | ウィジェット対応必須 |
| Scrapbox連携 | Scrapbox API | ページ取得・リンク構造取得 |
| リンクグラフ | ローカルDB or グラフDB | グラフ探索の効率性 |
| Embedding | OpenAI / Claude Embedding | 意味的類似度（補助的に使用） |
| 生成エンジン | Claude API | ページ編集・変奏の生成 |
| webページレンダリング | HTML/CSS生成 → WKWebView | エディトリアルレイアウト |
| 地層保存 | ローカルストレージ | 生成ページの時系列保存 |

## 7. 開発フェーズ（案）

### Phase 0：検証
- Scrapbox APIからのデータ取得とリンクグラフ構築
- LLMによるイマージュ分節の精度検証
- 断片選択→ページ生成のパイプラインをCLIで検証

### Phase 1：最小構成
- iOSウィジェット（焦点イマージュの表示）
- タップ展開→生成webページの表示
- Scrapbox素材のみ（外部素材は後回し）

### Phase 2：拡張
- 外部素材（Spotify、書籍、画像）の統合
- 地層保存・閲覧機能
- 装置自体の螺旋（相互作用履歴に基づく配合の自己変容）

### Phase 3：成熟
- 沈黙の設計（何も出さない日）の導入
- watchOS / macOS対応
- 音声インターフェース（AirPods連携）の検討

## 8. リスクと緩和策

| リスク | 深刻度 | 緩和策 |
|--------|--------|--------|
| 反芻思考の誘発 | 高 | 段階的深さで主体性保証。古い断片を優先 |
| タスク化衝動 | 中 | 直近の記述の確率を下げる |
| 鈍化（風景化） | 中 | メディアタイプ多様化、非等間隔更新 |
| ナルシシズム | 中 | 七対三の配合、agentの他者性維持 |
| 消費ループ化 | 中 | 最適化の抑制、差異の反復の設計 |
| ソースモニタリング混乱 | 低 | 出典を辿れる設計（欄外注釈） |
| Scrapbox API制限 | 低 | 差分同期、ローカルキャッシュ |

## 9. 成功指標

従来のエンゲージメント指標（DAU、セッション時間、リテンション）は、このプロジェクトの思想と矛盾する。

### 適切な指標（案）
- レイヤー2への展開率（焦点を見て、さらに開いたか）
- レイヤー3への遷移率（生成ページから原典に飛んだか）
- Scrapboxへの書き込み発生率（装置の使用後にScrapboxで何か書いたか）
- 地層の閲覧頻度（過去の生成ページを見返したか）

### 測定しないもの
- 使用頻度（多いほど良いという前提を置かない）
- セッション時間（長いほど良いという前提を置かない）
- ストリーク
